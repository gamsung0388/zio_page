# ZIO HOME — 노래책자 UI 1차 구현

**Vue 3 + JavaScript + Vite 기반 프런트엔드 UI 데모**입니다. 현재 운영 중인 zio-home 사이트를 직접 수정한 것은 아니며, 기존 프로젝트와 별도로 먼저 실행해서 디자인을 확인하는 용도입니다.

## 실행

```bash
npm install
npm run dev
```

콘솔에 출력된 개발 서버 주소(기본적으로 http://localhost:5173)를 엽니다.

## 화면 주소

- `#/` — 홈 (지오 중심 배너)
- `#/songs` — 노래책자 목록/검색/장르 필터
- `#/songs/demo-001` — 노래 상세
- `#/songs/new` — 곡 등록
- `#/songs/demo-001/edit` — 곡 수정
- `#/schedule` — 2차 방송 일정 자리표시자
- `#/about` — 지오 소개

## 구현된 항목

- 데스크톱 우측 콘텐츠 + 좌측 사이드바, 모바일 반응형 메뉴
- 등록·수정 동일 폼 컴포넌트, 실시간 카드 미리보기
- 5단계 숙련도 잎사귀, 연습 상태, 신청 풍 개수
- 검색, 장르 필터, 최신/이름순 정렬
- 시연용 추가/수정/삭제는 메모리에서만 반영되며 새로고침하면 초기화됨
- 업로드 이미지는 데모 미리보기로만 사용됨
- 실제 지오 프로필 이미지(대화에서 제공받은 이미지)를 메인에 사용
- 비공개 메모는 공개 상세 화면에서 표시하지 않음

## 의도적으로 빠진 기능

- Cloudflare Workers API / D1 읽기·쓰기
- 계정 로그인 및 관리자 권한 검사
- 실서비스 데이터 연동
- 이미지 R2 업로드 / 영구 저장
- 방송 중 여부, 스트리밍 재생, 일정 데이터
- 실제 곡 신청과 결제 기능

중요: 화면에 보이는 `등록`, `수정`, `삭제` 버튼은 모두 브라우저 메모리상의 데모 데이터만 바꿉니다. **권한 없는 관리자 UI 보호는 이 데모에 구현되어 있지 않으므로 실제 서비스에 그대로 공개하면 안 됩니다.** 실제 운영에 적용하기 전 인증·권한 처리가 선행되어야 합니다.

## 실제 `E:\zio` 프로젝트에 연결할 때

1. 기존 프로젝트를 별도로 백업하거나 새 Git 브랜치 사용
2. 현재 소스 구조와 라우팅을 먼저 점검하고 컴포넌트·CSS 위주로 옮기기
3. 기존 Worker, D1 마이그레이션, API 계약, 인증 로직을 삭제하지 않기
4. `src/services/songService.js`의 메모리 메서드를 기존 API 호출로 단계적 교체
5. API가 제공하는 데이터 필드를 `UI_SPEC.md`의 화면 데이터와 매핑
6. 관리자 전용 등록·수정·삭제 UI는 서버 측 권한 검증 후 노출
7. 모바일 테스트 → 실제 배포
