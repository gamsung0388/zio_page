# 22. 관리 메뉴와 디자인 개선

## 운영과 관리의 역할

방문자가 보는 **지오의 공간**, 콘텐츠를 다루는 **운영**, 홈페이지 설정을 다루는 **관리**로 나눴습니다. 운영에는 노래 관리와 일정 관리를 두고, 관리에는 **관리자 관리**, **메뉴 관리** 두 항목을 둡니다. `/admin`은 두 관리 기능을 선택하는 첫 화면입니다. 비밀번호 초기화·본인 변경은 관리자 관리의 하위 메뉴를 유지합니다.

노래 등록·CSV·백업은 노래 관리에, 일정·주간 이미지·메모·가이드는 일정 관리에 남깁니다. 서로 다른 데이터의 작업을 관리 메뉴 하나에 모두 모으면 다시 찾기 어려워집니다. 앞으로 프로필·소개·연락 링크 같은 사이트 설정은 관리에 묶을 수 있습니다. 변경 이력·운영 기록도 관리에 어울리지만 이번에는 구현하지 않았습니다. 기존 기능의 백업은 해당 작업 화면에서 찾도록 유지합니다.

## 메뉴 관리 사용법

1. 로그인 후 **관리 → 메뉴 관리**를 엽니다.
2. 기본 메뉴의 이름·같은 위치 안 순서·표시 여부를 바꿉니다. 홈은 항상 표시합니다.
3. **새 링크 추가**에서 이름, HTTPS 주소, 표시 위치를 지정합니다. 새 링크는 최대 20개입니다. 운영 위치의 링크는 로그인한 관리자에게만 보입니다.
4. 미리보기에서 확인한 뒤 **메뉴 저장**을 누릅니다. 편집만으로 홈페이지에 즉시 저장되지 않습니다.

기본 페이지의 연결 대상과 위치는 고정합니다. 기본 메뉴는 숨길 수 있고 추가한 링크는 삭제할 수 있습니다. 관리자 관리·메뉴 관리는 편집 목록과 분리해 항상 접근할 수 있게 유지합니다. 메뉴 숨김은 페이지 접근 권한 변경이 아닙니다. 공개 페이지 자체를 비공개로 바꾸지는 않습니다. 비공개 노래·메모·관리 API의 기존 서버 권한 검사는 유지합니다.

기존 지오 소개 페이지를 기본 메뉴에 노출했습니다. 외부 링크는 새 창으로 열며 `noopener noreferrer`를 적용합니다. 공백·자격 증명·HTTPS 이외 주소·알 수 없는 필드·중복 ID·기본 메뉴 제거를 서버에서 거부합니다. 링크 주소를 서버에서 대신 불러오지 않습니다.

편집 중 이탈·로그아웃 확인과 탭 내 임시 초안 복구를 제공합니다. 초안에는 당시 버전도 보관합니다. 다른 관리자가 먼저 저장하면 내 입력은 유지하고 덮어쓰기는 막습니다. **최신 설정 불러오기**는 내 편집을 버린다는 확인 후 수행합니다. 오래 열린 다른 브라우저의 메뉴는 새로고침 시 갱신됩니다.

| `src/services/useSiteNavigation.js`    | 세션 준비·계정 전환 시 메뉴 조회, 저장 후 공통 메뉴 반영                             |
| `src/services/useNavigationEditor.js`  | 편집 상태·저장·초안·충돌·이탈 확인                                                   |

기존 공통 API 클라이언트, 인증·Origin·CSRF, 요청 취소·응답 보호, 오류 알림, Modal, 초안 저장을 재사용합니다. 계정 API·노래 API·일정 API를 새로 작성하거나 mock으로 교체하지 않았습니다. 메뉴 조회는 동일 계정의 매 페이지 이동마다 반복하지 않습니다.

추가 실행 migration은 **`migrations/0007_site_navigation.sql`**이고 `database/migrations/0007_site_navigation.sql`은 참고 사본입니다. `site_navigation`은 `id=1`인 한 행의 설정과 `revision`, 수정 시각·수정자 참조를 저장합니다. 기존 테이블은 변경하지 않습니다. 미저장 상태는 행 없이 코드 기본값과 revision 0을 반환합니다. 최초 저장도 조건부 INSERT로 동시에 만든 설정을 덮어쓰지 않습니다.

## API

| 메서드 / 경로               | 계약                                                                                                   |
| --------------------------- | ------------------------------------------------------------------------------------------------------ |
| `GET /api/navigation`       | 표시 중인 공개·바로가기 메뉴만 `{items}`로 반환. 운영 위치의 이름·URL, revision·수정자는 포함하지 않음 |
| `GET /api/admin/navigation` | 인증된 관리자에게 전체 `{items,revision,updated_at}` 반환                                              |
| `PUT /api/admin/navigation` | `{items,expected_revision}` 저장. 기존 세션·강제 비밀번호 변경·Origin·CSRF 검사 적용                   |

항목은 `{id,label,area,href,visible}`입니다. revision은 0 이상의 정수이고 저장 버전 불일치는 **409 NAVIGATION_CONFLICT**, 잘못된 메뉴는 **422 NAVIGATION_VALIDATION**, 잘못된 버전은 **422 NAVIGATION_REVISION**입니다. 응답은 no-store입니다. 공개 응답에는 숨긴 링크나 운영 링크를 섞지 않습니다.

## UI·UX 분석과 적용

기존 화면은 같은 비중의 버튼과 관리 기능이 연속해 보여 진입 우선순위가 약했습니다. 계정·콘텐츠 작업이 섞인 메뉴도 찾는 과정을 길게 만들었습니다. 이번에는 메뉴 계층·여백·색·주요 행동의 위치를 함께 정리했습니다.

- 관리 홈에 지오 이미지, 부드러운 그린 배경, 인사 문구를 넣고 두 관리 기능을 큰 카드로 구분했습니다. 실제 데이터가 없는 통계·활동 수치는 만들지 않았습니다.
- 기존 아이콘 컴포넌트로 탐색 표현을 통일하고 현재 메뉴를 표시합니다. 소개 페이지의 활성 메뉴 표시도 바로잡았습니다.
- 메뉴 편집은 위치별 목록과 저장 전 미리보기로 나눴습니다. 표시·순서·수정 행동은 일정한 자리에 두고 숨김 상태를 글자와 스위치로 함께 표현합니다.
- 모바일은 한 열 배치와 충분한 조작 영역을 사용하고 저장 버튼을 화면 아래에 유지합니다. 긴 주소가 옆으로 화면을 밀지 않도록 처리했습니다.
- 오류 문구·링크 설명·레이블, 키보드 초점·모달·모바일 메뉴 동작을 유지·검증합니다. 저장하지 않은 편집과 서버 충돌을 구분해 안내합니다.

### 다음 개선 우선순위

1. **실제 콘텐츠 채우기**: 소개 문구·대표 이미지·곡 데이터가 화면의 완성도에 가장 큰 영향을 줍니다. 연동 승인 전 실시간 방송 상태나 일정 자동 인식은 표시하지 않습니다.
2. **노래책 탐색 다듬기**: 곡이 쌓인 뒤 검색 결과·필터·숙련도 표현의 밀도를 실제 사용으로 확인합니다. 앨범 이미지는 사용 가능한 데이터·출처·이용 조건을 정한 뒤 연결합니다.
3. **계정 관리 흐름**: 계정이 늘면 검색·목록 밀도·대상 확인을 보강합니다. 현재 규모에서는 표와 다수의 설정을 추가하지 않습니다.
4. **사이트 정보 편집**: 소개·프로필·방송 링크를 자주 바꿀 필요가 생기면 관리에 설정 기능을 추가합니다. 실제 편집·저장 기능 없이 빈 메뉴를 만들지는 않았습니다.

추가 유료 서비스나 이미지 생성·원격 링크 미리보기 요청을 도입하지 않았습니다. 설정은 작은 D1 한 행에 저장하고 화면 스타일은 관리 페이지에서 나눠 읽도록 했습니다.

### 실행 결과

- 프로덕션 빌드 성공. 기존 package.json·의존성·Wrangler 설정 변경 없음.
- Node 단위·실제 D1 통합 90개, 브라우저 58개, UI 참고 화면 6개: **총 154개 통과**.
- 새 메뉴 테스트는 실제 격리 D1 저장·재조회·공개/운영 링크 분리·동시 수정·초안 복구·이탈 확인·중복 조회 방지를 검증했습니다.
- PC 1920×1080·1440×900, 태블릿 768×1024, 모바일 390×844·360×800의 관리 홈·계정·메뉴·링크 입력창을 확인했습니다.
- 초기에 발견한 내부 링크 href 누락과 폼 레이블 접근성 문제를 수정하고 전체 검증을 다시 수행했습니다.
- 전체 브라우저 회귀 중 메뉴 최신 설정 재조회 1건은 로컬 응답 13.1초에 대해 화면 단언의 5초 대기를 넘겼습니다. 추적에서 200 완료를 확인했고, 응답 완료를 기다리도록 테스트를 수정한 뒤 메뉴 6개를 재검증했습니다. 고유 항목 수에는 같은 항목의 재실행을 중복 계산하지 않았습니다.
- 기존 일정의 다섯 화면 크기 검사는 전체 실행에서 60초 한도를 넘겨 분리 재실행했습니다. 화면·데이터 검증을 생략하지 않고 같은 기준으로 확인했습니다.
- 마지막 점검에서 새 링크 입력 중 뒤로 가기 보호, 긴 메뉴 이름 말줄임, 모바일 메뉴의 44px 이상 터치 높이, 보조 글자 대비와 메뉴 로딩 문구를 보완했습니다.
- 로컬·원격 D1을 각각 비공개 .local/backups 경로에 SQL 백업 후 migration 0007 적용. 기존 노래·관리자·개별 일정·주간 메모 개수 동일, 새 설정은 미저장 기본값으로 시작합니다.
- 사용자 기존 database/migrations/0001_initial.sql은 작업 전 백업과 SHA-256이 같고 UI 참고 ZIP은 보존했습니다. 두 파일은 커밋하지 않습니다.

### 미연결·범위와 통합 주의

요청한 이름·순서·표시·새 링크 추가는 실제 API·DB에 연결했습니다. SOOP 자동 인식·공개 일정·사이트 프로필 편집·변경 이력은 추가하지 않았습니다. 새 링크는 HTTPS 외부 링크이며 임의 내부 페이지 생성 기능은 아닙니다. 표시 위치 간 이동은 추가한 링크에서 지원하고 기본 기능의 위치는 고정합니다.

배포 전 migration 0007이 필요합니다. 오래 열린 화면은 새로고침하세요. 기본 메뉴 변경은 shared/navigation.js에서, 고정 관리 항목은 admin-navigation.js에서 관리하고 임의의 URL을 기존 내부 경로로 바꾸지 않습니다. 메뉴 숨김과 페이지 권한을 혼동하지 않도록 안내를 유지합니다. 초안에는 기존 버전을 보존하며 409 발생 시 자동 덮어쓰기나 자동 재시도하지 않습니다.
