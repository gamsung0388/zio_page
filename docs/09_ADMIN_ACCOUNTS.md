# 09. 관리자 등록 · 비밀번호 변경 · 초기화

2026-10-16 추가 요청 반영. 기존 관리자 로그인 후 사용하는 기능입니다.

## 화면 사용

로그인하면 `/admin`의 **관리자 관리 메뉴**에서 사용할 기능을 선택합니다. 로그인한 관리자에게 상단 **관리자 관리** 메뉴를 표시하고, 홈·노래책자를 새로고침해도 로그인 상태를 확인합니다.

- **관리자 등록**: 노래 관리 화면의 버튼 또는 관리자 관리 화면의 등록 버튼을 누릅니다. 아이디(영문·숫자·점·밑줄·하이픈 3~80자), 표시 이름(최대 80자), 비밀번호(12~256자)와 확인 값을 입력합니다. 표시 이름을 비우면 아이디를 사용합니다. 중복 아이디는 거부하며 기존 계정을 덮어쓰지 않습니다.
- **관리자 관리** `/admin/users`: 계정 목록·활성 상태·비밀번호 변경 필요 상태를 확인하고 새 관리자를 등록합니다. 초기화 버튼은 표시하지 않습니다. 모든 활성 관리자는 동일한 등록·관리·초기화 권한을 가집니다.
- **관리자 비밀번호 변경** `/admin/password`: 현재 비밀번호와 새 비밀번호를 입력합니다. 새 비밀번호는 현재 비밀번호 및 초기화 비밀번호와 달라야 합니다. 변경 성공 시 모든 기기에서 로그아웃되며 새 비밀번호로 다시 로그인합니다.
- **관리자 비밀번호 초기화** `/admin/password-reset`: 초기화 메뉴에서 관리자가 대상 계정의 초기화 버튼을 누르고 확인합니다. 사용자 지정 초기 비밀번호 **`qwer1234!@#$`**로 설정되며 기존 세션은 전부 폐기됩니다. 해당 계정은 다음 로그인 후 비밀번호를 반드시 변경해야 합니다. 내 계정을 초기화하면 즉시 로그아웃됩니다. 다른 관리자를 초기화한 경우 작업자의 세션은 유지됩니다.

비밀번호 변경 필요 상태에서는 화면 이동뿐 아니라 서버 API에서도 노래 조회·편집·CSV·관리자 등록·초기화를 차단합니다. `/api/admin/me`, 로그아웃, 본인 비밀번호 변경만 허용합니다. 기존 또는 CLI 계정이 초기화용 비밀번호를 사용하고 있으면 로그인 시 동일한 변경 정책을 적용합니다.

## API

| 메서드 | 경로 | 요청 / 응답 |
|---|---|---|
| GET | `/api/admin/users?page=1&page_size=20` | 관리자 목록과 pagination. page_size 최대 100 |
| POST | `/api/admin/users` | `username, display_name, password, password_confirmation` → 201, `id, username, display_name, created_at` |
| PATCH | `/api/admin/password` | `current_password, password, password_confirmation` → 200, 모든 세션 폐기·쿠키 만료 |
| POST | `/api/admin/users/:id/reset-password` | → 200, `ok, must_change_password, logged_out`. 새 비밀번호를 응답에 포함하지 않음 |

로그인과 `/api/admin/me`의 `user.must_change_password`는 boolean입니다. 변경 전 허용되지 않은 관리 요청에는 403 `PASSWORD_CHANGE_REQUIRED`를 반환합니다. 중복 아이디는 409 `USERNAME_EXISTS`, 입력 오류는 422 `VALIDATION`, 잘못된 현재 비밀번호는 403 `CURRENT_PASSWORD_INVALID`입니다. 비밀번호 확인 요청은 계정별 15분 10회 제한을 적용합니다.

모든 API는 세션 인증과 `no-store`를 사용합니다. 변경 요청은 동일 출처와 CSRF 토큰을 검사합니다. 목록/생성 응답에는 비밀번호, 해시, salt, 세션 토큰을 포함하지 않습니다. 비밀번호는 기존 PBKDF2 정책으로 해싱하고 계정 등록·초기화·변경마다 새 난수 salt를 사용합니다. 비밀번호 관련 이벤트 로그에는 자격 증명을 기록하지 않습니다.

## DB와 배포

`migrations/0003_admin_password_change.sql`은 `admin_users.must_change_password` 컬럼을 추가합니다. 기존 계정의 비밀번호와 세션, 노래 데이터는 그대로 유지하며 기본값은 0입니다. 실행본과 설계 사본을 모두 보존합니다.

운영 DB를 백업한 뒤 원격 마이그레이션을 적용하고 Worker를 배포합니다. 테스트는 Miniflare 및 `.local/e2e/state`의 별도 DB를 사용하며 운영 계정이나 노래를 생성·초기화하지 않습니다. 최초 관리자 생성은 기존 CLI를 사용합니다. 로그인할 수 있는 관리자가 전혀 없으면 Cloudflare 계정 접근 권한으로 CLI에서 새 관리자 ID를 생성한 뒤 기존 계정을 복구할 수 있습니다.

## 검증

단위·통합·CLI 테스트 33개, 브라우저 테스트 8개, 프로덕션 빌드를 통과했습니다. 익명·CSRF·외부 Origin·만료/비활성 세션 차단, 중복 동시 등록, 비밀번호 해싱과 응답 보호, 세션 폐기, 초기 비밀번호 및 강제 변경, 본인 변경, 확인 재입력, 모바일 화면을 검증했습니다. 초기화/변경 테스트는 운영 DB에서 수행하지 않습니다.
