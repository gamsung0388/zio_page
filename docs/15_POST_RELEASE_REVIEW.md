# 15. 최종 배포 후 추가 개선 분석

분석일: 2026-10-16 (Asia/Seoul). 배포 소스는 `34d490e`(기반 통합 `7a7eb67`), Worker 버전은 `622f0f2c-c3b1-4b60-93da-a4d7326bbade`입니다. [14 수정·배포 기록](14_REMEDIATION_RELEASE.md)의 R1–R9 보완 이후를 기준으로 분석했습니다.

기존 노래·관리자 기능, 일정 초안·권한·충돌·이미지·백업, 미완성 노래 초안까지 총 86개 테스트가 통과했습니다. 운영 확인의 범위·한계와 증거 파일은 14번 문서에 기록합니다. 아래 항목은 다음 개발 순서이며, 운영 데이터를 변경해 문제를 재현하지 않고 현재 소스/설치 의존성을 근거로 판단했습니다.

## 1. 노래의 동시 수정

`server/repositories/songs.js`의 updateSong은 WHERE id=?로 저장합니다. `src/pages/SongEditor.vue`와 `src/services/song-adapter.js`는 편집 폼의 전체 필드를 PATCH로 전달합니다. 두 관리자가 같은 초기 상태에서 편집하면 나중 요청이 먼저 수정한 필드까지 이전 값으로 덮을 수 있는 구조입니다. 이는 코드 경로에서 확인한 결과이며 운영의 실제 노래를 덮어쓰는 재현은 하지 않았습니다.

이번에 추가한 노래 초안 복구는 초안 작성 후 updatedAt이 바뀌었으면 확인을 받습니다. 일반 편집 도중 다른 관리자가 저장하는 상황까지 차단하는 서버 버전 조건은 별도 작업입니다. 일정의 expected_revision/409와 같은 원자적 버전 검사를 노래 저장에 적용하고, 충돌 시 두 내용을 비교할 수 있게 하는 것이 우선입니다. 저장 중 버전 검사이므로 권한·비공개 메모 분리는 그대로 유지해야 합니다.

## 2. 개발 도구 경고

현재 설치 기준 `npm audit --omit=dev`는 0건입니다. 전체 audit는 miniflare 및 전이 의존성 sharp/undici에 high 3건을 보고했습니다. `.local/remediation-review/audit-full.json`에 원본 결과를 보관했습니다. 이 결과를 운영 브라우저/Worker 실행 의존성에 같은 경고가 있다는 의미로 해석하면 안 됩니다.

Wrangler·Cloudflare Vite plugin·Miniflare/workerd 버전을 함께 맞추는 호환성 점검 후 패치 업데이트를 적용하고, 현재의 API/브라우저/이미지 테스트를 통과시키는 순서가 적절합니다. 이번 기능 안정화에서 강제 의존성 교체나 검증되지 않은 다운그레이드는 하지 않았습니다. 구체적인 안전 버전은 해당 업데이트 작업 시점의 공지와 lockfile로 다시 확인해야 합니다.

## 3. 수정 이력과 복원

일정의 revision은 충돌 검사에 쓰이며 과거 내용을 조회하는 이력은 아닙니다. 현재 admin_schedule_weeks는 최신 payload 하나를 보관합니다. updated_by는 기록하지만 화면 응답에는 관리자 정보가 포함되지 않습니다. 잘못 저장한 뒤 돌아갈 경로는 미리 만든 JSON/DB 백업입니다.

다음에는 최근 몇 차례 저장본과 수정 관리자·시간을 관리자 전용으로 보여주고 되돌리기 전 비교를 제공하는 편이 좋습니다. 이력 보관 개수를 제한해 저장량이 계속 늘지 않게 설계합니다. 전체 JSON은 현재도 내보낼 수 있고, 가져오기는 검증한 파일에서 한 주를 선택해 현재 주에 수동 저장하는 방식입니다. 여러 주 복원은 대상 날짜·기존 존재 여부·충돌을 미리 보고 각각의 버전을 검사하는 별도 흐름으로 확장할 수 있습니다.

## 4. 실제 앨범 표지와 링크

현재 공개 노래의 cover와 links는 실데이터 어댑터에서 빈 값으로 설정하며 기본 장식 이미지를 사용합니다. 운영 폼에는 영구 저장되지 않는 업로드/링크 입력을 숨겼습니다. UI 참고 앱의 파일 선택은 운영 업로드 기능이 아닙니다.

이미지 출처와 저장 방식을 먼저 정하고 노래 API·D1 필드 및 기본 이미지 대체 규칙을 함께 연결하는 순서가 맞습니다. 현재 이미지 보안 정책은 같은 출처와 data:만 허용하므로 외부 표지 URL을 그대로 넣는 경우 정책·이미지 실패 처리도 함께 점검해야 합니다. SOOP 심사 승인 여부와 음악 메타데이터/앨범 표지의 출처는 별개의 연결 조건입니다.

## 5. 사용성과 유지보수

주간 이미지 편집기는 PC 좌우 배치, 모바일 큰 입력창을 제공합니다. 월간 달력은 모바일에서도 7열이므로 긴 일정의 전문을 읽으려면 날짜 창을 열어야 합니다. 월간/일정 목록 전환을 더하면 시간과 여러 줄 내용을 읽기 쉬워집니다. 이는 현재의 저장 오류가 아니라 다음 사용성 기능 후보입니다.

새 코드 형식은 정리했지만 기존 main.css, 새 공통 main.css, integration.css의 전역 스타일은 함께 사용합니다. 색상/간격 토큰과 컴포넌트 범위를 단계적으로 정리하고 현재 5개 화면 크기의 캡처를 기준으로 비교하면 이후 관리자 화면 변경의 영향을 줄일 수 있습니다.

## 현재 확인의 한계

- 실제 운영 관리자 비밀번호를 사용하거나 계정을 생성/초기화하지 않았습니다. 실제 인증 CRUD와 저장은 운영과 분리된 테스트 D1에서 검증했습니다.
- 배포된 편집기의 보안 정책/CSP와 PNG 출력은 격리된 QA 브라우저에서 관리자 API 읽기 응답만 대체해 확인했습니다. 이는 실제 운영 관리자 로그인/저장을 수행했다는 의미가 아닙니다. 해당 브라우저의 API 쓰기는 차단했습니다.
- 확인 시점의 공개 노래가 0개이므로 실제 운영 곡 상세 화면은 검사 대상이 없었습니다. 상세·비공개 메모 분리·CRUD는 테스트 DB에서 검증했습니다.
- 초안은 동일 탭에서 최대 24시간의 임시 보관입니다. 다른 기기 이동·탭 종료 후 복구에는 서버 저장 또는 JSON 백업을 사용해야 합니다.

공개 일정표, SOOP 자동 방송/신청 연동은 현재 관리자 전용 도구와 구분된 확장 범위입니다. 이번 배포에는 추가 서비스나 유료 연동을 도입하지 않았습니다.
