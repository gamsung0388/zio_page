# 19. 일정 목록 날짜 선택과 사용 가이드

작업일: 2026-10-17 (Asia/Seoul). 기반 커밋 `24bf414`. 목록에서도 원하는 날짜로 일정을 등록하고, 운영 중인 기능을 설명하는 가이드를 추가한 뒤 배포·추가 분석을 요청한 작업입니다.

## 목록에서 날짜를 정하는 흐름

- 일정 목록 위에 **등록할 날짜** 선택기와 **선택한 날짜에 일정 등록** 버튼을 추가했습니다. 날짜는 직접 입력하거나 네이티브 달력으로 선택합니다.
- 선택한 날짜를 등록창의 시작일과 종료일에 채웁니다. 위쪽 **새 일정 등록**도 목록 보기에서는 이 날짜를 사용합니다. 등록창 안의 시작/종료 날짜·시간 편집은 유지합니다.
- 목록의 날짜별 묶음에도 **＋ 일정 추가**를 제공합니다. 이 버튼은 해당 묶음의 날짜로 등록창을 엽니다. 달력의 날짜 클릭도 기존처럼 클릭한 날짜를 사용합니다.
- 표시 중인 달과 다른 날짜를 선택해도 등록할 수 있습니다. 조회하는 달은 입력 중에 바꾸지 않고, 저장한 일정이 현재 달에 없으면 해당 달로 이동합니다. 저장 후 날짜 선택기에 저장한 시작일을 남깁니다.
- 날짜를 비우거나 2000~2099년 범위를 벗어나면 등록창을 열지 않고 날짜 칸에 초점과 설명을 표시합니다.
- 날짜 선택만으로 API나 DB에 쓰지 않습니다. 등록창에서 실제 저장할 때 기존 관리자 API와 서버 검증을 사용합니다.

## 관리자 사용 가이드

경로는 `/admin/schedule/guide`이며 일정 관리 메뉴의 **사용 가이드**에서 엽니다. 기존 로그인과 강제 비밀번호 변경을 적용하고, 로그인 후 이 경로로 복귀할 수 있도록 안전한 복귀 경로 목록에 추가했습니다.

가이드는 날짜·시간/기간 등록, 주간 이미지 만들기, 주간 메모 편집/삭제, 두 종류의 JSON 백업/복구, 초안/동시 수정, 자주 묻는 질문을 설명합니다. 운영 화면과 같은 색상과 카드 구성을 사용하며 목차에서 해당 제목으로 이동·초점을 옮깁니다. 제목이 상단 메뉴에 가리지 않도록 여백을 적용했습니다.

일정 목록과 가이드를 왕복할 때 보고 있던 달·보기 방식·선택 날짜·일정 구분을 유지합니다. PC는 4개 메뉴, 좁은 화면은 2×2 메뉴로 배치합니다. 가이드 내용은 정적 안내로 별도 데이터 조회나 저장을 추가하지 않습니다. 기존 공통 로그인 확인은 수행합니다.

## 보존 범위와 검증

- 기존 API·Workers·D1 스키마·세션·CSRF·동시 수정 검사·주간 메모 삭제 계약은 변경하지 않았습니다. migration, 외부 서비스, 새 의존성은 없습니다.
- 테스트는 격리된 로컬 D1을 사용합니다. 운영 계정이나 일정을 검증용으로 저장·수정하지 않습니다.
- 새 브라우저 검증: 목록 날짜 선택과 두 등록 버튼/다른 달 저장, 빈 날짜·날짜 묶음/달력 바로 등록, 가이드 로그인 복귀/문맥 유지, 가이드 무저장/5개 반응형 크기를 확인합니다.
- 기준: 1920×1080, 1440×900, 768×1024, 390×844, 360×800. 목록·입력창·가이드 캡처 총 15개를 `.local/list-guide-review/screenshots/`에 보관합니다.
- 작업 전 파일·Git 상태는 `.local/list-guide-before-1792212632972/`에 보관했습니다. 기존 사용자 SQL 수정과 참고 ZIP은 이번 커밋에서 제외합니다.
