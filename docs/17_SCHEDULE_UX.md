# 17. 일정 관리 UI·UX 점검과 개선

작업일: 2026-10-17 (Asia/Seoul). 기반 소스는 `916bc03`이며 기존 개별 일정, 주간 이미지 메모, 스케줄 이미지의 사용 흐름을 점검했습니다. 공개 화면과 관리자/노래의 기능 계약은 유지합니다.

## 발견한 불편과 반영 내용

| 항목 | 확인한 문제 | 적용한 개선 |
|---|---|---|
| 모바일 저장 | 날짜·시간을 입력하다 보면 저장 버튼이 창 아래로 사라짐 | 제목/닫기와 저장 영역을 고정하고 입력 영역만 스크롤. 취소·일정 저장이 첫 줄, 저장 후 이미지가 둘째 줄 |
| 입력 순서 | 시작일·종료일 다음에 시작·종료 시각이 떨어져 있어 한 일시를 확인하기 어려움 | 시작/종료를 별도 묶음으로 배치. PC는 나란히, 모바일은 위아래로 표시하고 날짜·시각을 충분한 너비로 입력 |
| 입력 실수 | 종료가 시작보다 이르거나 빈 값일 때 저장 버튼마다 안내 방식이 다름 | 두 저장 버튼에 같은 검증을 적용. 첫 오류 칸에 초점을 옮기고 오류 테두리·설명 연결. 안내는 저장 영역에 표시 |
| 자정과 기간 | 다음 날 종료를 직접 계산해야 하고 총 기간이 바로 보이지 않음 | 총 시간/일수 안내. 같은 날의 종료 시각이 시작보다 이르면 다음 날 종료 버튼을 제공하며 직접 선택해야 적용 |
| 새 일정 문맥 | 다른 달을 보고 새 일정을 누르면 오늘 날짜로 열림 | 선택 날짜 → 보고 있는 달의 오늘 → 해당 달 1일 순서로 초기 날짜 선택. 현재 일정 구분도 기본 입력에 적용 |
| 저장 후 가시성 | 구분을 바꾸어 저장하면 현재 필터에 가려져 저장 실패처럼 보일 수 있음 | 저장한 구분과 현재 필터가 다르면 전체 구분으로 바꾸고 알림. 선택 날짜 밖으로 옮기면 날짜 필터 해제 |
| 일정 목록 읽기 | 작은 날짜 문자열과 평면 목록으로 날짜·시간·기간 파악이 어려움 | 날짜·요일별 묶음, 읽기 쉬운 시간/기간, 이전 날짜부터 이어지는 일정 표시. 여러 날 일정도 목록에는 한 번만 표시 |
| 탐색과 빈 화면 | 특정 날짜 더 보기를 새로고침하면 사라지고 빈 목록에서 다음 행동이 불분명 | 날짜 선택을 URL에 보존. 월 전체/전체 구분 복귀와 해당 날짜 등록 버튼. 조회 건수는 선택 범위에 맞춰 표시 |
| 조작 구분 | 삭제·백업·다시 불러오기와 저장이 한 화면에 섞임 | 추가 작업은 이름이 보이는 접는 영역으로 분리. 삭제는 별도 색상으로 구분하고 기존 확인 유지 |
| 주간 메모 저장 직후 | 저장창 닫힘과 선택 날짜 URL 정리가 따로 끝나 빠른 새로고침에서 같은 창이 다시 열릴 수 있음 | 날짜 URL 정리를 완료한 뒤 저장창을 닫아 저장 완료 시점과 화면을 일치 |
| 화면 일관성 | 일정 조회 중 노래를 불러온다는 문구, 이미지 저장이 개별 달력을 갱신하는 것처럼 보이는 문구 | 일정 전용 로딩 문구와 이미지 메모 저장 범위 안내. 기존 노래 로딩의 기본 문구는 유지 |
| 키보드·작은 화면 | 조작 초점과 선택 상태가 약하고 일부 버튼/글자가 작음 | 초점 테두리, 선택 버튼 대비, 주요 조작 44px, 입력 16px, 요일/주말 구분. Escape에서 미저장 확인 및 닫은 뒤 초점 복귀 검증 |

360px에서 날짜와 시간을 한 줄로 배치한 안은 실제 캡처에서 네이티브 시간의 분이 잘려 제외했습니다. 최종 모바일 입력은 날짜와 시간을 각각 한 줄로 표시합니다. 저장 영역은 스크롤과 관계없이 유지합니다.

## 보존한 동작과 구현 범위

- Worker/API/D1 스키마, 서버 권한·Origin·CSRF·revision, 기존 노래·관리자 데이터는 변경하지 않았습니다. 이번 변경에 migration은 없습니다.
- 공통 Modal 자체를 바꾸지 않고 일정 입력 전용 클래스에 고정 영역을 적용했습니다. 다른 관리창 레이아웃에 영향을 주지 않습니다.
- 안내/입력 검증은 기존 `validateEventPayload`를 사용합니다. 서버도 동일한 기존 검증을 계속 수행합니다. 프런트엔드 어댑터는 날짜 표시, 총 기간, 첫 오류 칸 안내만 담당합니다.
- 재로그인 초안 복구, 저장 전 이동 확인, 동시 수정 충돌, JSON 백업/선택 가져오기, 이미지 수동 반영은 유지합니다.
- 새 외부 서비스·라이브러리·자동 폴링을 추가하지 않았습니다. 날짜별 묶음과 기간 안내는 이미 받은 데이터를 브라우저에서 처리합니다.
- 작업 전 상태/파일은 `.local/schedule-ux-before-1792210804446/`에 보관했습니다. 기존 사용자 변경 `database/migrations/0001_initial.sql`과 참고 ZIP은 이번 커밋에서 제외합니다.

## 검증

최종 단위·API 68개, 실제 브라우저 39개, 참고 UI 6개로 총 **113개 통과**했습니다. 주간 메모 저장 후 새로고침과 기존 노래·관리자·이미지 기능까지 전체 검증했습니다. 테스트 DB는 `.local/e2e/state`에 격리하며 운영 계정이나 일정을 테스트용으로 생성/수정하지 않습니다.

- 화면 기준: 1920×1080, 1440×900, 768×1024, 390×844, 360×800. 달력·목록·입력 총 15개 캡처를 확인했습니다.
- 새 회귀 검증: 한국 날짜/요일·총 기간과 초점 대상 3개, 모바일 고정 저장·자정 종료, 월/구분 기본값과 저장 후 표시, 날짜별 목록/새로고침, 키보드 확인과 초점 복귀의 실제 브라우저 흐름 4개.
- 이 단계의 실제 브라우저는 Windows Microsoft Edge이며 한국 입력 시각을 다른 시간대에서도 검증했습니다. 실제 iPhone/Android 기기의 네이티브 선택기와 화면 키보드 검증은 수행하지 않았습니다.
- 기존 별도 UI 참고 앱의 RouterLink 등록 경고는 이전부터 있던 현상이며 이번 운영 앱 오류로 해석하지 않습니다.
