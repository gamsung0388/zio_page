# 화면 설계 요약 — ZIO HOME UI v0.1

## 핵심 원칙

- 지오 캐릭터가 중심, 판다는 부수 장식.
- 아이보리색 배경 / 화이트 카드 / 딥 그린 사이드바 / 라임 포인트.
- 반응형: PC 1920×1080 우선 / 태블릿 / 모바일 390×844 대응.
- 같은 헤더, 카드, 버튼, 입력 필드, 숙련도·상태 표시를 재사용.
- UI 확정 단계이므로 **D1, Workers, 관리자 인증은 연결하지 않음**.

## 컴포넌트

- `AppSidebar` : 메뉴, SOOP 링크, 모바일 오버레이
- `AppHeader` : 공통 상단 바, UI PREVIEW 라벨
- `LeafRating` : 숙련도 0~5, 등록·수정에서는 클릭 선택
- `StatusPill` : 미연습/연습중/완료
- `SongCard` : 재사용 곡 카드, 메인 목록/노래책자
- `SongFormView` : 등록과 수정 동시 담당, 우측 실시간 미리보기

## 화면 구조

| 화면 | PC | 모바일 |
|---|---|---|
| 홈 | 배너 + 노래 미리보기 2열 + 안내 2열 | 배너 + 세로 리스트 |
| 노래책자 | 4열 카드 + 상단 검색/필터 | 1열 가로형 곡 리스트 |
| 상세 | 곡 정보 2열(본문/사이드) | 단일 세로 스크롤 |
| 등록/수정 | 폼 + 우측 미리보기 | 단일 폼 + 하단 미리보기 |

## 데이터 필드

`id`, `title`, `artist`, `genre`, `level`(1~5), `practiceStatus`(`미연습`/`연습중`/`완료`), `balloonCount`(신청 풍 개수), `cover`, `description`, `privateMemo`, `links`(label/url), `createdAt`, `updatedAt`.

> `privateMemo`는 실제 서비스에서는 서버/API 레벨에서 관리자 외 응답에 포함되지 않게 해야 함. 버튼 숨기기만으로는 권한 제어가 불가능함.

## 현재 의도적 제약

- 노래 정보와 아티스트는 **화면 확인용 예시 데이터**이며 지오 실제 곡 목록이 아님.
- 공개 서비스가 아닌 UI 시연용: 등록·수정·삭제는 일시적인 브라우저 메모리 동작.
- 외부 관련 링크는 http/https 검사만 한 상태. 서버 연결 시 재검증 필요.
- 커버 업로드는 Data URL 브라우저 미리보기만 제공. 운영용은 R2 등 외부 저장소 설계 필요.
- 모바일 등록 기능은 UI 구성 확인을 위해 노출, 실제 운영에서 권한에 따라 제한.

## 권장 기능 연결 순서

1. API 응답 구조 확정 후 GET 목록/상세 연결
2. 계정 인증 및 서버 권한 검증
3. 관리자 POST/PATCH/DELETE 기능 연결
4. 이미지 업로드 연결
5. 상세 링크 검증 및 공개/비공개 필드 분리
6. 일정표 2차 개발
