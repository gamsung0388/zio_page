## 배포 후 측정

### 달력 계산

로컬 Node 24.11.1에서 2028-04-01~04-30 종일 일정 합성 데이터로 42일 배치를 계산했습니다. 한 번 준비 실행 후 5회 측정한 중앙값입니다.

| 일정 수 | 현재 방식 | 경계 사전 계산 실험 | 날짜별 개수 일치 |
| --- | ---: | ---: | --- |
| 100개 | 9.87ms | 0.09ms | 일치 |
| 2,000개 | 220.57ms | 1.40ms | 일치 |

실험 코드는 분석용이며 제품에 적용하지 않았습니다. 이 수치는 운영 브라우저·Cloudflare Worker의 처리 시간이나 사용량이 아닙니다. 종일 합성 데이터 비교이므로 실제 적용 전 시간 지정·자정 경계·기간·수정 후 재계산 검증이 필요합니다. 성능 개선 가능성을 확인한 근거로 사용합니다.

### 화면 이동과 요청

운영 파일을 사용하는 격리 브라우저에서 초기 목록 로딩 이후 다음 여섯 동작을 측정했습니다: 목록→달력, 달력→목록, 새 일정 열기, 취소, 가이드 열기, 목록으로 돌아가기. 관리자 GET 응답은 테스트 자료로 대체하고 쓰기는 차단했습니다.

- `/api/admin/me` 6회, 일정 목록 GET 1회로 총 7회의 API 요청을 관측했습니다.
- 이는 프런트엔드가 발행한 요청 수입니다. 실제 운영 D1 읽기 횟수·청구액·Worker CPU를 측정한 값은 아닙니다.
- 새 날짜 입력 자체는 이동·조회·저장을 발생시키지 않습니다.
- 가이드 JavaScript는 해당 화면 진입 시 지연 로딩됐고, 목록·가이드에서는 이미지 출력용 `html2canvas`를 요청하지 않았습니다. 기존 분리 로딩은 유지할 가치가 있습니다.
- 페이지 오류는 없었습니다. 관리 화면의 짧은 로그인 확인 재사용은 비용 절감 후보지만, 현재 요청량만으로 무료 플랜 초과를 예측하지 않습니다.

### 파일 크기

배포와 일치한 로컬 빌드 파일의 원본 크기와 `zlib.gzipSync` 압축 크기입니다. 브라우저의 실제 전송량이나 캐시 적중률 측정은 아닙니다. KB는 1,000바이트 기준입니다.

| 파일 | 원본 | gzip |
| --- | ---: | ---: |
| 이미지 출력 `html2canvas` | 199.47KB | 46.56KB |
| 공통 CSS | 95.84KB | 20.06KB |
| 진입 JavaScript `index` | 50.12KB | 19.78KB |
| 새 사용 가이드 | 11.10KB | 4.15KB |

공통 CSS의 화면별 분리와 중복 스타일 정리는 낮은 우선순위의 후보입니다. 이미지 도구와 새 가이드는 이미 지연 로딩되므로, 단순 파일 크기만 보고 공통 번들로 합칠 이유는 없습니다. CSS 정리는 다섯 화면 크기와 공개 홈페이지까지 확인할 범위를 정한 뒤 진행합니다.

### 설치 의존성 감사

현재 lockfile 기준 `npm audit --omit=dev --json`은 0건입니다. 전체 감사는 `miniflare`·`sharp`·`undici` 세 패키지 항목을 high로 분류했습니다. 이는 서로 다른 보안 권고가 정확히 세 개라는 뜻은 아니며 전이 의존성도 포함합니다. 이 결과만으로 배포된 Worker에 동일한 공격 경로가 존재한다고 판단하지 않습니다.

이번 작업에서는 의존성을 변경하거나 자동 수정하지 않았습니다. 갱신 시 실제 사용 경로·상위 도구 호환성과 감사 결과를 다시 확인해야 합니다. 새 유료 서비스나 주기적 폴링은 위 개선안에 필요하지 않습니다.
